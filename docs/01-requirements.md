# Requirements Specification — Checkon (เช็คก่อน)

เอกสารนี้เป็นขั้นตอน **Requirements** ของ SDLC สำหรับระบบจัดการของใช้ในบ้าน (Checkon / เช็คก่อน)

## 1. ภาพรวมระบบ (Overview)
ระบบช่วยผู้ใช้บันทึกและติดตามของใช้ในบ้าน (จำนวน ราคา ขนาด หมวดหมู่ วันหมดอายุ ร้านค้า ผู้ซื้อ รูปภาพ)
พร้อมสรุปค่าใช้จ่าย/งบประมาณ แจ้งเตือนของใกล้หมด และสแกนบาร์โค้ดเพื่อเติมข้อมูลอัตโนมัติ
มีระบบสมาชิก (สมัคร + ยืนยัน OTP ทางอีเมล + ตั้งรหัสผ่าน), โปรไฟล์ลูกค้า และการล็อกแอปด้วย PIN/ไบโอเมตริก

## 2. ผู้มีส่วนเกี่ยวข้อง (Stakeholders / Actors)
| Actor | คำอธิบาย |
|-------|----------|
| User (สมาชิก) | ผู้ใช้งานที่สมัครและล็อกอิน จัดการของใช้ในบ้านของตนเอง |
| System (auth) | ออก/ตรวจ JWT, จัดการ OTP และการตั้ง/รีเซ็ตรหัสผ่าน |

## 3. Functional Requirements
| ID | ความต้องการ | Priority |
|----|-------------|----------|
| FR-01 | สมัครสมาชิก: กรอกคำนำหน้า/ชื่อ/username/อีเมล → รับ OTP ทางอีเมล → ยืนยัน → ตั้งรหัสผ่าน → ล็อกอินอัตโนมัติ | Must |
| FR-02 | ล็อกอินด้วยอีเมลหรือ username, รีเฟรช token, เปลี่ยน/รีเซ็ตรหัสผ่าน | Must |
| FR-03 | โปรไฟล์ลูกค้า: ดู/แก้ไข คำนำหน้า, ชื่อ-สกุล, username, รูป, สถานะ, วันเกิด | Must |
| FR-04 | สร้าง/ดู/แก้ไข/ลบ "สินค้า" (ชื่อ จำนวน ราคา ขนาด หน่วย หมวดหมู่ วันหมดอายุ ร้านค้า ผู้ซื้อ รูป) | Must |
| FR-05 | สแกนบาร์โค้ดเติมข้อมูลสินค้าอัตโนมัติ (ชื่อ/ยี่ห้อ/ขนาด/หมวด/ร้าน/รูป) หรือกรอกเอง | Must |
| FR-06 | สรุปค่าใช้จ่าย (รวม + แยกตามเดือน/หมวด) และตั้งงบประมาณเทียบยอดใช้จริง | Must |
| FR-07 | แสดงรายการ "ใกล้หมด" (วันหมดอยู่ภายใน N วันข้างหน้า) | Must |
| FR-08 | ล็อกแอปด้วย PIN 6 หลัก + ปลดล็อกด้วยไบโอเมตริก (ลายนิ้วมือ/ใบหน้า) และเปลี่ยน PIN ได้ | Should |

## 4. Non-Functional Requirements
| ID | ความต้องการ |
|----|-------------|
| NFR-01 | สถาปัตยกรรมแบบ Microservice แยกแต่ละ service ชัดเจน (5 services) |
| NFR-02 | Database-per-service (แต่ละ service มีฐานข้อมูลของตัวเอง ไม่อ่านข้าม DB) |
| NFR-03 | สื่อสารระหว่าง service และกับ client ผ่าน REST ผ่าน API Gateway |
| NFR-04 | โค้ดออกแบบด้วย Clean Architecture + Hexagonal (domain/application/infrastructure/interface + ports & adapters) |
| NFR-05 | รันได้ด้วย Docker Compose ในเครื่อง dev |
| NFR-06 | มี input validation (class-validator) และ error handling แบบ `{ domain, code, message }` |
| NFR-07 | ความปลอดภัย: รหัสผ่าน hash ด้วย bcrypt, JWT access/refresh, OTP มีวันหมดอายุ+จำกัดจำนวนครั้ง, PIN เก็บ hash local-only |
| NFR-08 | รองรับหลายภาษา (TH/EN) และธีมสว่าง/มืดในฝั่ง client |

## 5. Use Cases (ย่อ)
- **UC-01 สมัครสมาชิก**: User กรอกข้อมูล → ระบบส่ง OTP → User ยืนยัน OTP → ตั้งรหัสผ่าน → ระบบสร้างบัญชี + โปรไฟล์ + ล็อกอิน
- **UC-02 ล็อกอิน/จัดการรหัสผ่าน**: User ล็อกอิน (อีเมล/username) → รับ token; เปลี่ยน/รีเซ็ตรหัสผ่านได้
- **UC-03 จัดการสินค้า**: User เพิ่ม (สแกนหรือกรอกเอง)/แก้/ลบสินค้า → ระบบอัปเดต
- **UC-04 ดูสรุป/งบประมาณ**: User เปิดหน้า Home/งบประมาณ → ระบบคำนวณยอด + เทียบงบ → แสดงผล
- **UC-05 ของใกล้หมด**: User เปิดหน้าแจ้งเตือน → ระบบคืนรายการที่วันหมดใกล้ถึง
- **UC-06 ล็อกแอป**: User ตั้ง PIN/ไบโอเมตริก → ครั้งถัดไปต้องปลดล็อกก่อนเข้าแอป

## 6. ขอบเขตที่ยังไม่รวมในเฟสนี้ (Out of Scope)
- Multi-user sharing / household ร่วมกันหลายคน
- Push notification จริง (ใช้การแสดงผลในแอปแทน)
- Message broker (ใช้ REST synchronous ไปก่อน)
- OTP/อีเมลผ่าน provider จริง (dev ใช้ Ethereal + log console)
